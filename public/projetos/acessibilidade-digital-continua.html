Guia introdutório · Passagem

Acessibilidade digital contínua

Descobrir quando uma mudança no site cria uma barreira para quem o utiliza.

Documentado · implementação não iniciada

Imagine uma loja virtual em que uma pessoa navega usando apenas o teclado. Uma atualização pode deixar o botão de compra inacessível. Este projeto propõe testar caminhos da loja a cada alteração e mostrar quais problemas surgiram, quais já existiam e quais foram corrigidos.

Para quem: Equipes que desenvolvem sites e precisam acompanhar problemas de acessibilidade durante as mudanças do produto.

Um exemplo simples

Uma alteração remove o nome acessível de um botão. O teste automático encontra o problema, compara com a versão de referência e registra a nova barreira. Uma regra previamente definida decide se essa alteração deve ser bloqueada até a correção.

  1. Uma alteração chega ao repositório
  2. Jornadas automáticas procuram barreiras
  3. Os achados são comparados com a referência
  4. Uma decisão explica o que precisa ser corrigido

A demonstração planejada usa um e-commerce próprio e dados sintéticos. Testes automáticos cobrem parte da acessibilidade; não substituem toda a avaliação humana nem certificam conformidade. Auditoria com participantes reais está fora do MVP.

Quatro termos para entender a proposta
Achado
Um problema encontrado pelo teste, como um campo sem identificação.
Baseline
Versão de referência usada para saber o que mudou.
Regressão
Um problema novo ou que voltou depois de uma alteração.
Gate
Regra de aprovação ou bloqueio da alteração, acompanhada de uma justificativa.
