Guia introdutório · Crivo IA

Governança, avaliação e observabilidade de IA

Verificar se uma nova versão de uma aplicação de IA pode ser liberada com confiança.

Documentado · implementação não iniciada

Imagine um assistente de atendimento de uma loja. Ao mudar seu modelo ou suas instruções, algumas respostas podem melhorar e outras piorar. Este projeto propõe repetir testes conhecidos, comparar as versões e guardar as razões da decisão de liberar ou bloquear a mudança.

Para quem: Equipes que mantêm aplicações com IA e precisam entender mudanças de comportamento, investigar falhas e justificar liberações.

Um exemplo simples

Uma nova instrução faz o assistente responder incorretamente a um caso crítico de atendimento. O sistema executa uma coleção de testes, compara com a versão anterior e preserva os resultados. Uma falha determinística pode bloquear a liberação; um resultado inconclusivo permanece identificado como tal.

  1. Uma versão candidata é registrada
  2. Uma coleção de testes é executada
  3. Resultados são comparados com a referência
  4. A decisão e suas evidências são preservadas

A demonstração planejada usa um assistente de e-commerce e dados sintéticos, com provedor de IA simulado para testes reproduzíveis. Não exige uma API paga. Resultados estatísticos e decisão de bloqueio são separados; apenas FAILED determinístico bloqueia o CI.

Quatro termos para entender a proposta
Governança
Regras e registros que permitem entender quem decidiu e por quê.
Observabilidade
Informações sobre o que aconteceu durante uma execução, para investigar problemas.
Suite e baseline
Uma coleção de testes e uma versão de referência para comparar resultados.
Gate de release
Decisão registrada sobre a liberação de uma nova versão.
