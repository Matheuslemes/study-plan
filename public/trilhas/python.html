Resumo Executivo

Objetivo da trilha: formar um Python pleno forte para backend, automação e IA aplicada em produção.

Visão geral

Python nesta trilha não é tratado como linguagem auxiliar simples. Ele é uma competência de engenharia para construir APIs, workers, pipelines de dados, integrações, produtos com IA, RAG, agentes, automações e microsserviços complementares ao ecossistema Java/Spring.

O foco final é posicionar você como backend Java com capacidade real de entregar soluções de IA em produção usando Python: FastAPI para serviços de IA, Django/DRF quando houver necessidade de produtividade e admin, pandas/scikit-learn/PyTorch para dados e ML, e LangChain/LangGraph/LlamaIndex para RAG e agentes controláveis.

Backend profissional exige

  • API REST com versionamento, paginação, filtros, ordenação, status codes e padrão de erro consistente.
  • Autenticação e autorização com JWT/OAuth2, permissões por recurso e validação de escopo.

  • Redis para cache, rate limit, locks, sessões temporárias ou fila leve.
  • Workers para tarefas demoradas, retries, DLQ, idempotência e monitoramento.
  • Docker, pipeline CI/CD, logs estruturados, health check, métricas e deploy rastreável.

RAG em produção precisa conter

  • ingestão de documentos, parsing, limpeza e chunking controlado;
  • embeddings, vector store, metadata filters e ACL por documento;
  • retrieval com similaridade, busca híbrida e reranking quando necessário;
  • resposta com fontes/citações, grounding e controle de alucinação;
  • avaliação com métricas de faithfulness, context relevance e answer relevance;
  • logs auditáveis, custo por requisição, latência p95, fallback e rate limit;
  • proteção contra prompt injection, vazamento de dados e uso indevido de ferramentas.

Consulta rápida

Resumo objetivo para revisão e entrevistas.

Revisão
Pergunta Resposta curta esperada
FastAPI ou Django? FastAPI para APIs modernas, microsserviços e IA; Django para produto web, admin, ORM integrado e produtividade full-stack.
Async sempre melhora performance? Não. Ajuda em I/O concorrente; para CPU-bound use multiprocessing, workers, otimização ou serviço separado.
Por que typing importa? Melhora contrato, documentação, refatoração, validação com Pydantic e reduz erro em projetos grandes.
Quando usar worker? Para tarefas demoradas, instáveis ou reprocessáveis: e-mail, parsing, IA, relatórios, ingestão e integrações externas.
O que torna um RAG bom? Boa ingestão, chunking correto, retrieval relevante, citações, avaliação, ACL, logs e controle de alucinação.
O que medir em LLMOps? Custo, latência, erro, qualidade, faithfulness, contexto usado, taxa de fallback e versão do prompt/modelo.
O que é prompt injection? Tentativa de manipular o modelo para ignorar regras, revelar dados ou usar ferramentas de forma indevida.

FastAPI com health check e exception handler

from fastapi import FastAPI, Request
from fastapi.responses import JSONResponse
from pydantic import BaseModel

app = FastAPI(title="Python AI Service", version="1.0.0")

class ApiError(Exception):
    def __init__(self, message: str, status_code: int = 400):
        self.message = message
        self.status_code = status_code

@app.exception_handler(ApiError)
async def api_error_handler(request: Request, exc: ApiError):
    return JSONResponse(
        status_code=exc.status_code,
        content={
            "type": "about:blank",
            "title": "Application error",
            "status": exc.status_code,
            "detail": exc.message,
            "instance": str(request.url.path),
        },
    )

@app.get("/health")
async def health():
    return {"status": "UP"}
